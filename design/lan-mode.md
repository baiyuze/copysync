# 局域网直连：不用服务器也能配对和同步

> 状态：已实现，随 1.4.0 发布
> 代码：`client-core/internal/transport/lan/`（发现、信令、配对、地址簿）、`transport/signed/`（签名与校验）、`peers/manager.go`（两条通道合并）
> 验证：`transport/lan/lan_test.go`、`peers/manager_test.go`、`tools/natlab/`（局域网场景）、Mac 与 Windows 虚拟机实机测试
> 相关：[多出口网络的 NAT 打洞](nat-traversal.md)

## 一、问题

1.3 之前，两台电脑必须先连上同一台信令服务器，才能配对、知道对方在线、交换连接信息。即使两台就在同一个路由器下面，用户也得先找一台常开的电脑部署服务器。

服务器在这里只做三件事：

| 服务器的职责 | 局域网里用什么代替 |
|---|---|
| 发现：谁在线、在哪个地址 | mDNS（DNS-SD）广播 |
| 转发签名的信令 | 设备之间直接用 UDP 收发 |
| 配对码：码 → 公钥 | 在局域网里直接交换 |
| STUN / TURN | 同一局域网里用不上，host candidate 就能直连 |

信任模型本来就把服务器当成不可信的转发者：信令逐条签名，配对靠人工核对指纹，DTLS 指纹随签名一起传。把转发者从服务器换成局域网，安全性不变。

## 二、原型实测

动手之前，先用一个临时程序（mDNS 注册与浏览，加固定 UDP 端口互发 hello）在 Mac 和 Windows 虚拟机之间测了几种情况。虚拟机在 Parallels 的共享网络里，与 Mac 同一网段，网络类型是「公用」。

### Windows 防火墙

| 情况 | 结果 |
|---|---|
| 程序没有任何防火墙规则 | Windows 能发现 Mac（自己发出的查询，回答作为回包放行）；Mac 发现不了 Windows（Windows 回答不了查询）。Windows 主动打招呼后，双方都能收发 |
| 有显式的入站阻止规则（相当于弹窗时点了取消） | 同上。有状态防火墙对回包一律放行，阻止规则只挡主动连进来的包 |
| 只有 Mac 知道 Windows 的地址，Windows 不知道 Mac 的 | 不通：Mac 的包被挡，Windows 不会主动发 |
| 只有 Windows 知道 Mac 的地址 | 通 |
| 两边都知道对方地址 | 通 |
| 删掉程序的入站规则，再加一条 UDP 允许规则 | 只有 Mac 知道地址时也通了 |

结论：

- **被挡的一方只要先发包就能通。** 所以设计成「两边都往对方发」，谁也不依赖入站规则。
- **Windows 内置的 mDNS 入站规则只放行系统的 Dnscache 服务**，我们自己的进程收不到别人的查询。改用系统的 DNS-SD 服务（`DnsServiceRegister`）注册后，即使有阻止规则，Mac 也能立刻发现 Windows。浏览仍用 pion/mdns，不受影响。
- 弹窗点过取消、或者跨网段时被连的一方是 Windows，就需要放行。界面上提供一个按钮，用一次 UAC 运行 netsh 修好。

### macOS 15 的本地网络权限

从终端运行的程序不受限制，但同一个程序打包成 App、由 launchd 启动（与后台服务一样）时，往局域网地址发包直接返回 `sendto: no route to host`。对方先发来的包仍然能收到，也能回复。

这说明 1.3 的后台服务在 macOS 15 上其实也连不到局域网地址。它和 Windows 虚拟机之间显示「直连」，是因为 Parallels 的 NAT 让虚拟机的包看起来来自 Mac 自己的 IP，恰好绕开了限制。两台 Mac 之间如果都没拿到权限，谁也连不上谁。

处理办法：

- 后台服务的 Info.plist 加上 `NSLocalNetworkUsageDescription`（中英日本地化）与 `NSBonjourServices`。
- LaunchAgent 写上 `AssociatedBundleIdentifiers`，让系统知道后台服务属于 CopySync.app（TN3179 的建议）。
- 后台服务发现发往本机直连网段的包返回 `EHOSTUNREACH` 时，报告「被系统拦截」，界面提示用户去「系统设置 → 隐私与安全性 → 本地网络」打开。

## 三、方案

### 1. 两条通道并存

`peers.Manager` 同时持有信令服务器客户端和局域网通道：

- **在线**：服务器说在线、局域网里可达、P2P 已连通，任一成立即可。服务器断开只清掉服务器那一半。
- **发送信令**：签一次名，局域网可达就走局域网，连着服务器就也经服务器转发。接收方的 `signed.Verifier` 两条路共用一份 nonce 记录，只处理先到的那份。
- **配对结果通用**：配对只是交换公钥，局域网里配好的设备，以后加上服务器照样能跨网络同步。

签名与校验从信令客户端里抽到 `transport/signed`，并补上一条检查：`to_device_id` 必须是本机。服务器按收件人转发，这条检查以前可有可无；局域网里谁都能把截到的消息转发给第三台设备，必须有。

### 2. 发现

- 服务类型 `_copysync._udp`，实例名每次启动随机（`copysync-` 加 12 位十六进制），不带设备名。
- TXT：`v=1`，`t=当日令牌`，配对码开放期间加 `p=1`。
- 令牌是 `sha256("copysync-lan|" + device_id + "|" + UTC 日期)` 的前 8 字节。已配对的设备按昨天、今天、明天各算一遍就能认出对方；同一网络里的其他人看到的只是一串每天都变的字符，无法跨天关联。
- Windows 上由系统的 DNS-SD 服务回答查询（见上一节），其他平台由 pion/mdns 回答。网络变化时（本机地址集合变了）重新加入组播、重新广播。

### 3. 局域网信令

- 固定 UDP 端口 8788，被占用时（同一台 Mac 上两个用户都登录着）退回随机端口，端口随 mDNS 和地址一起告诉对方。
- 每个包是 4 字节魔数 `CSL1` 加 `LanPacket`，上限 16 KB，按来源限速。
- 已配对设备之间收发的就是服务器转发的那种 `Signed`。上线通知是 `SignalMessage` 里新增的 `LanHello`：自报的地址、要不要回一条、自己多久发一次。
- 对每台还没连通的设备，每 10 秒往它可能在的地址发 hello（已连通时 30 秒保活）。候选地址按顺序取：最近一次收到它消息的来源、mDNS 发现的、它自报的、地址簿里的，最多 12 个。
- 收到有效消息就记下来源地址，并标记可达；超过对方声明间隔的三倍没收到，视为不可达。
- 信令发往对方最近的来源地址，150 毫秒后再补发一次，抵消 UDP 偶尔丢包；重复的那份被 nonce 去重。

### 4. 地址簿与跨网段

- 新表 `device_addrs(device_id, addr, last_seen)`，每台设备最多 8 个，随设备一起删除。
- 跨网段时 mDNS 过不去，配对时由用户输入对方配对码下面显示的地址。配对双方都记下对方的地址，之后任意一方换了地址，只要另一方没换，就能重新找到。
- 两边都换了地址时，在设备菜单里「输入它的地址」。不做网段扫描：在公司网络里会被当成端口扫描。
- Tailscale 不转发 mDNS，但 100.x 地址就是普通的可达地址：配对时输入它，之后同样靠地址簿。

### 5. 配对

- 显示码的一方：码在服务器和局域网两边同时开放（连着服务器时用服务器签发的码，否则本机生成，格式见 `proto/pairingcode`），一边用掉另一边就失效。错码 10 次作废。
- 输入码的一方：先在局域网里找，发往所有 `p=1` 的实例和用户输入的地址，每 500 毫秒重发，3 秒为限（输了地址时 5 秒）；找不到且连着服务器再去服务器兑换。
- 请求和回复都是 `LanPairInfo`，用自带的公钥签名，并校验 ID 由公钥派生；回复回显请求的 nonce，绑定到这次请求。配对码在局域网里明文传输，与服务器模式下服务器能看到配对码等价：防中间人靠的是用户核对指纹。
- 配对请求与回复本身证明了对方在哪个地址，收到即标记可达，确认后第一次连接不必再等 hello。

### 6. 其他改动

- 服务器地址默认为空。1.4.0 之前的默认值 `ws://127.0.0.1:8787/signal` 其实没有服务器在跑，升级时清空一次（配置文件记 `config_version`，只迁移一次）。
- 没有服务器时不探测公共 STUN：只在局域网里连，探测出口没有用，还会把公网 IP 暴露给公共服务器。
- 解除配对时断开 P2P 连接（以前不断开）。
- `copysync-cli`：`join CODE [ADDRESS]`、`address DEVICE ADDR`，`nat` 里加了局域网一节。

## 四、能覆盖哪些场景

| 两台电脑 | 结果 |
|---|---|
| 同一网段 | mDNS 发现，直连 |
| 不同网段，网段之间互通 | 配对时输入地址，直连；之后靠地址簿 |
| 同一 tailnet | 配对时输入 100.x 地址，直连 |
| 一台是没放行防火墙的 Windows | 只要它知道对方的地址（或由系统 DNS-SD 被发现后对方打招呼），就能连上 |
| 两台都是没放行防火墙的 Windows，跨网段，只有一边知道地址 | 连不上，需要在被连的一方点「放行」 |
| 两个网段之间被隔离（访客网络等） | 连不上，只能经两边都能访问的服务器中转 |
| macOS 15 没允许本地网络 | 对方先发来时能连；两台都是这样的 Mac 时连不上，界面提示去允许 |

## 五、验证

### 单元测试与集成测试

`transport/signed/signed_test.go`：签名与校验；同一条信令从两条通道到达只处理一次；收件人不是本机时拒收；未配对、冒用 ID、时间戳过期都拒收。

`transport/lan/lan_test.go`：两个实例绑在 127.0.0.1 的不同端口上，用内存网络代替 mDNS。已配对设备互相找到并收发信令、补发的那份被去重、地址记进地址簿；只靠记得的地址互相找到；未配对设备的 hello 不算数；局域网配对、按地址配对、码只能用一次、错 10 次后作废；可达状态过期；地址解析与令牌换天。

`peers/manager_test.go`：两个完整的 `peers.Manager`。没有服务器时配对、P2P 直连、双向收消息，解除配对后断开；不同网段时不输地址找不到、输了地址能配对并直连；关掉局域网只用服务器时原来的配对路径照常工作，错码立即被拒；服务器和局域网同时开着时，同一个码只能用一次。

`config/config_test.go`：旧默认地址清空、自己的服务器保留、只迁移一次。`store/store_test.go`：地址簿的排序、上限、随设备删除。

界面：`pairing_flow_test.dart` 覆盖显示本机地址、找不到时展开地址框并带地址重试、错码提示、侧栏的局域网状态与 macOS 拦截提示。

### NAT 打洞实验室

新增 `natlab lanpeer`：不起任何服务器，用真实的局域网通道连接，两端身份由种子派生，相当于已经配对。新增两种拓扑：同一网段（网桥）与两个网段（路由器，不做 NAT）。

| 场景 | 预期 | 结果 |
|---|---|---|
| 同一网段，靠 mDNS 发现 | 直连 | 通过 |
| 两个网段，一边记得对方地址 | 直连 | 通过 |
| 两个网段，两台都挡入站新连接，都记得地址 | 直连 | 通过 |
| 两个网段，两台都挡入站新连接，只有一边记得 | 连不上 | 通过 |
| 两个网段之间被隔离 | 连不上 | 通过 |

「两台都挡入站」用每台主机上的 `iptables -A INPUT -p udp -m conntrack --ctstate NEW -j DROP` 模拟没有放行规则的 Windows 防火墙，证明两边同时发包确实能穿过有状态防火墙。

### 实机验收

Mac 与 Windows 11 虚拟机，各跑一个用 `-tags fakeclip` 编译的后台服务（独立数据目录，不碰真实剪贴板），不配服务器。Windows 上的程序是新的路径，没有任何防火墙规则。

- 局域网配对成功，两边的安全指纹一致。
- 文本双向同步；5 MB 文件从 Mac 传到 Windows，SHA-256 一致。
- 两边都重启后约 1 秒重新直连。
- 新的一对在确认配对后立即直连；8788 被占用时退回随机端口，地址里自动带上端口。

## 六、踩过的坑

- **配对后的第一次连接要等 30 秒。** 确认配对后立即发起连接，但双方还没互发过 hello，局域网通道认为对方不可达，offer 发不出去，连接停在「连接中」直到握手超时。改为配对的请求与回复到达时就标记可达；offer 发不出去时立即复位，不等超时。
- **配对前就被发现的实例，配对后认不出来。** 令牌是按已配对设备算的，配对后要把已经发现的实例重新对一遍。
- **pion 的浏览每秒报一次同一个实例，还会报出无关的服务。** 只在地址或令牌变化、或超过 30 秒时才行动；校验服务类型与 `v=1`。
- **锁的顺序。** 局域网通道持锁时回调上层（取已配对设备、查 P2P 状态），上层持锁时又查局域网的可达状态。可达状态单独放在一把叶子锁里，回调一律在锁外。
- **Parallels 的 NAT 掩盖了 macOS 的拦截**，见第二节。
- **natlab 里新建 veth 时，第一个名字先在容器自己的命名空间里创建**，起名 `eth0` 会与容器的网卡冲突；`[[ … ]] && …` 放在函数末尾、条件不成立时会让函数返回 1，触发 `set -e`。

## 七、局限与后续

- 两台都没放行防火墙的 Windows、跨网段、只有一边知道地址时连不上，需要在被连的一方点「放行」。
- macOS 15 的本地网络授权弹窗只在屏幕解锁时出现。ad-hoc 签名的版本每次更新后，系统可能把它当成新程序重新询问；有了 Developer ID 签名后会稳定。
- 不做网段扫描。两边地址都变了要手动输入一次，台式机建议在路由器里固定地址。
- 只支持 IPv4。
